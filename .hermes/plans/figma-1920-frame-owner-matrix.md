## Composition foundation and lifecycle contract

- `UTKWindowBase` implements `IUTKCompositionPanel` explicitly. Composition `Open()` dispatches to virtual `Show()`; inherited `Close()` dispatches to virtual `Hide()`. Thus existing derived `Show/Hide` hooks, refresh-loop teardown, `UTKWindowManager.Register/Unregister`, per-window close buttons, and ESC stack membership stay intact.
- `UTKCompositionLifecycle` snapshots members before open/close iteration, making callbacks that mutate registration safe. `ToggleAll` closes the group if any sibling is open; otherwise opens the group. It does not synthesize a separate group ESC entry: each window still contributes its own existing ESC-stack entry.
- `UTKInventoryClusterComposition` is a narrow composition owner—not a generic screen framework. Inventory Open/Toggle now routes to inventory + detail; warehouse Open/Toggle(string) routes to inventory + detail + warehouse with territory passed through the existing WarehouseSystem owner. The warehouse-trigger OpenWarehouse route still refreshes/opens the group, while either public Toggle route toggles the active composition group. Independent close remains supported; the next group Toggle closes the group if any member is open, or reopens the configured group when all are closed. Existing public signatures/callers are preserved.
- The current `PanelSettings.asset` states ScaleWithScreenSize, reference 1440×900, width-match (`m_Match: 0`), not the Figma canonical 1920×1080. `FigmaCanvasLayout` scales positions/dimensions from resolved root size; no global PanelSettings change was made. Therefore exact 1:1 pixel size at 1920 needs final Unity panel/screen confirmation; proportional scale is a deliberate existing mechanism, not proof that the project’s 1920 runtime is identity scale.
