## 1. 완벽 분석

### 1.1 [확정] 호수 가운데 사각 박스들 = 노멀맵을 알베도로 사용한 것

**소스 입증** (WaterMaterialUpgrader.cs):
- 수면 머티리얼의 `_BaseMap`에 `Water_Normal_01.png`(**노멀 맵**)을 할당, 타일 **3×3** (`WaterTextureTiling`)
- 노멀 맵은 파랑-보라 톤 + 타일 경계가 있어 → 2048 수면 원판 위에 **3×3 파랑 사각 박스 격자**로 렌더 = 50 증상 그대로
- Idyllic 팩에 물 알베도는 존재하지 않음(노멀 2종 + 수련 잎뿐) — 노멀을 잘못 가져온 것
- 48에서 "수면이 서 있다"고 보였던 것도 같은 노멀맵 텍스처의 깊이 착시가 겹친 것

**수리**: `_BaseMap` 할당 제거(셰이더 그래프의 얕은/깊은 색 그라데이션만 사용) 또는 결정론 생성한 옅은 물 알베도. **전자 권장**(텍스처 추가 없이 박스 즉시 소멸).

### 1.2 호수 10개 → 더 늘리기 + 수면 높이 정밀화

- 현재 10개(LCG 시드 20260904). 사용자: "호수도 좀 더 늘어났으면"
- 증가 시 제약: 호수간 최소 250m, 스폰/성 반경 150m 배제, 맵 ±1000m — 14~16개까지 여유 있음
- 수면 높이는 이미 3단 지형+링 보정+−0.15 하강으로 정합(역전 경고 0건 유지 확인)

### 1.3 북쪽 설산 (Z2 후 재판정) — 미완성 요인

- Z2에서 north_snow 알베도 생성+북 L1 매핑까지 완료했으나, **50/51 시점의 Play가 Z2 컴파일 전이었을 가능성** + **스플랫 베이크가 X1 이전 캐시를 재사용했을 가능성**
- 추가 확인 필요: 월드 스플랫이 매 Play 재베이크되는지(캐시 없음) — Y1 구현상 Start에서 매번 베이크하므로 최신 텍스처 반영됨. 50 캡처 세션의 BakeWorldSplat 로그로 판정
- 보완책: 북쪽 고도 가중치가 "설원=고지대"로 실제 타는지 Make() 파라미터 재검증 + 북 tint를 살짝 밝게(0.98,1.00,1.08)

### 1.4 공중부양 착시 — 미완성 요인

- Z3의 BlobShadow(플레이어)/경사 30° 스킵/진폭 증폭은 적용됐으나, 49 대비 개선 폭이 시각적으로 부족했을 가능성
- 추가 요인: 그림자 방향(태양 각도)으로 그림자가 몸에서 떨어져 보이는 것 — 탑다운에서 접지감의 핵심은 **그림자가 아닌 수평선/가장자리**. 언덕 능선 라인이 읽히려면 굴곡 대비가 더 필요
- 보완책: ①릴리프 AO 강화 2차(골짜기 ×0.78까지), ②디테일 타일 18→12(텍스처가 언덕을 따라가는 느낌), ③플레이어 BlobShadow 반경 0.8/알파 0.35로 강화

### 1.5 단조로움 — Z4 적용 확인 후 부족분

- 숲 군락/꽃밭 14%/곡선 도로/호수 10개는 코드 적용됨 — 50 캡처가 Z4 컴파일 전이면 미반영
- 부족분 보강: 숲 군락 반경 100~180 → 120~220(더 큰 숲), 꽃밭 패치 크기 확대, 나무 수종당 스케일 변주(0.8~1.3 랜덤 — 예시의 자연스러운 크기 차)

## 2. 수리 계획 (AA1~AA4, 총 2일)

### AA1. 물 박스 제거 + 물 품질 (0.5일, 즉시)

1. `WaterMaterialUpgrader` TryCreateIdyllicShaderGraphMaterial: **_BaseMap/_MainTex 할당 제거** (노멀맵 알베도 오용 차단) — 셰이더 그래프 색 그라데이션만 사용
2. `_BaseMap` 없을 때 디테일 손실 보완: 셰이더 그래프 파라미터로 **거품/물결 라인 강도 살짝 상향**(있는 경우)
3. URP Lit 폴백 경로도 동일(_BaseMap 미할당, 순수 색)
4. 검증: 53번 — 박스 격자 소멸, 수면이 균일한 청록 그라데이션

### AA2. 호수 10 → 14개 (0.5일)

1. `LAKE_COUNT = 14`, LCG 시드 신규(예: 20260914L) — 기존 규칙 유지(간격 250m/성·스폰 150m 배제/경계 150m)
2. 배치 로그로 14개 좌표+waterLevel 확인, 역전 경고 0건
3. 수변 데코(갈대/연꽃) 자동 증가 확인

### AA3. 북 설산 확정 + 릴리프 보강 (0.5일)

1. **BakeWorldSplat 재베이크 확인 로그**로 최신 텍스처 반영 보장(캐시 없음 확인)
2. 북 tint 미세 상향 + L1(설원) 고도 가중치 재검증 — 51 재판정에서 설원이 안 보이면 L1/L2 고도 스왑
3. AO 2차: 골짜기 ×0.78, 디테일 타일 18→12
4. BlobShadow 강화: 반경 0.8/알파 0.35
5. 검증: 54번 — 북쪽 흰/연청 설산 + 공중부양 착시 완화

### AA4. 다양성 보강 (0.5일)

1. 숲 군락 반경 120~220 확대 + 나무 스케일 변주 0.8~1.3(결정론 해시)
2. 꽃밭 패치 크기 확대
3. 검증: 55번(월드) — 숲/꽃밭/도로/호수 14개 종합 판정

## 4. 소요: 2일 (AA1 즉시, AA2∥AA3 병렬, AA4 마무리)

## 4-5. [사용자 추가 요구] 잔디·꽃 표면 커버 — 예시 8 재현 (AA5, 1일)

> "텍스처에 잔디들도 붙어있지 않은데 예시 8번처럼 지형에 잔디와 중간중간 꽃들도 심겨져 있게"

### 팩 자산 조사 완료 — 전부 존재 (신규 제작 불필요)
- **`Prefabs/Grass_01.prefab` / `Grass_02.prefab`** — Idyllic 잔디 풋(tuft) 프리팹
- `Models/Grass/Grass.fbx` + `Textures/Grass/Grass_01/02/03.png`(흰색+알파) — 잔디 카드 텍스처. **이 흰색 마스크의 원래 용도가 이것**: 잔디 카드 재질(`Materials/Grass/Grass_01.mat`)에 `_Custom_Color/_Enable_Top_Color` 속성이 있어 **녹색 틴트로 착색해 사용하는 구조** (지면 알베도로 쓰면 흰색이 되었던 43번 사고와 정반대 맥락)
- **`Prefabs/FlowerMeadow_{Blue,Orange,Pink,Purple,Red...}.prefab` 8색** — 꽃밭이 **단일 메시로 된 패치** (한 프리팹 = 꽃밭 한 타일) — 예시의 단색 꽃밭을 즉시 재현 가능

### 구현
1. **잔디 커버 시스템** (`TerrainGrassCover.cs` 신규 또는 IdyllicDecoPlacer 확장):
   - Grass_01/02 프리팹을 **GPU Instancing**으로 대량 배치
   - 밀도: 꽃밭/숲 마스크 내부 2~3개/㎡, 일반 지면 0.5개/㎡ (예시처럼 잔디가 "깔린" 느낌은 밀집 패치로)
   - 배치 좌표: 결정론 시드(국가 시드+7), 스폰/성/호수 수변 제외, 경사 30° 스킵
   - **컬링 필수**: 플레이어 반경 50~60m만 활성(그룹 관리) — 예상 수량 6~9만 개라 인스턴싱+컬링 없이는 불가
   - 크기 변주 0.7~1.3, 약간의 기울기 변주(±8°)로 자연스러움
2. **FlowerMeadow 패치 배치**: 꽃밭 마스크 중심(패치당 1개)에 FlowerMeadow_* 프리팹 배치(스케일 6~12m 랜덤, 국가별 색 선호: 동=혼합/북=보라/남=빨강/서=노랑) — 예시 8의 "꽃이 깔린 지면" 즉시 재현
3. **기존 Flowers 개별 배치와 병행**: 흩어진 개별 꽃(예시의 중간중간 꽃) 유지
4. 성능 게이트: 배치 후 프레임 측정, 목표 초과 시 잔디 밀도 50% 하향 + 컬링 반경 축소
5. 검증: 55번 — 잔디/꽃이 지면에 깔린 모습(예시 8 비교)

### 소요: +1일 (AA4와 병렬 가능 — 총 2.5일)
