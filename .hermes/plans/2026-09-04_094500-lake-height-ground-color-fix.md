## 2. 근본 원인 (소스+로그 검증 완료)

### 2.1 호수가 치솟는 메커니즘 — 수학으로 입증

**현재 waterLevel 산식** (TerrainGenerator.cs 380-385행):
```
waterLevel = ComputeNationHeight(중심) - depth + LAKE_WATER_OFFSET(1.5)
```
- `ComputeNationHeight` = **카브(호수 파내기) 적용 전 기저 높이** (재귀 방지 설계)
- 최종 지형 = 기저 − depth×s (ApplyLakeBasins, 반경 1.3r로 완만 파냄)

**결함 논리**:
- waterLevel은 **호수 중심 1점의 기저 높이**만으로 결정
- 그런데 새 지형은 파장 200m급 구릉(FBM 진폭 동7m~북13m) — **호수 직경 80~140m 사이에서도 지형이 2~4m 변함**
- 시뮬 (Lake_0 실측 로그): surface=1.14, 반경 0.9r 지점 지형=2.02 → **물이 해안보다 0.9m 아래** (호수가 아니라 움푹 파인 구멍)
- 구형 EnforceSurfaceAboveTerrain: 반경 0.9r에서 최고 지형 2.02를 감지 → 수면을 **2.17로 들어올림**
- 이제 수면 2.17 > 주변 지형(0.5~2m 구간 다수) → **수면 원판이 땅 위로 떠서 관통** → 위에서 보면 "치솟은 판" = 42 증상

**구조적 결론**: 물 높이를 "지형이 높아지면 물을 올리는" 방식(Enforce)으로 맞추는 건 근본적으로 틀렸다.
올바른 방향은 반대 — **수면을 고정하고, 지형(호숫가)을 수면에 맞춰 눌러 담는 것**.

### 2.2 바닥 색 이상 — 2개 요인

**요인 1 (확정): Ground_Grass_Mat 3사본 중 `Assets/URP/` 사본의 _BaseMap이 다시 null**
- 에디터 자동 저장 사고 **5번째 재발** (auto 커밋 61562659/628c29bd로 확인: NULL↔22d5b6(Terrain_Grass) 왔다갔다)
- 씬의 외곽 `Ground`(2000m 평면, scale 200)가 이 **NULL 머티리얼(Ground_Grass)** 사용 → 이상 단색
- 기존 가드 `EnsureGroundGrassBaseMap()`은 Resources 하 사본만 자동 복구 — **Assets/URP 사본은 에디터 전용 경로**인데, 42 캡처 세션에서는 복구 로그 없음 (가드 실행 여부 불명확 → 로그 확인 결과 "자동 복구" 로그 0건 = **가드가 이번엔 Resources 경로만 복구하고 에디터 경로는 실패했거나, 복구 후 에디터가 다시 덮어씀**)

**요인 2 (확정): Ground_Inner의 지면 머티리얼 교체 타이밍**
- GameSetup:654-683이 Ground_Inner에 `Resources/URP/Ground_Grass_Mat`(NULL인 사본이었던 시기 존재)를 적용한 뒤
- TerrainTextureApplier.Start가 나중에 `Terrain_East_Mat`(스플랫)으로 교체 — 이 순서가 꼬이면 씬뷰에 임시 머티리얼이 보임
- 42의 cyan 격자무늬 = 스플랫 텍스처가 극저해상도(100×100 메시 + 2048 스플랫) 원거리에서 미세 패치로 뭉개져 보이는 것 + 조명 부재(Ambiance 미부착 세션) 조합 가능성. **Play 중 Game 뷰에서 재확인 필요** (씬뷰는 라이트/기즈모가 달라 색 왜곡이 큼)

### 2.3 지형 굴곡이 안 보이는 이유 (명확)
- 현재 Ground_Inner 메시는 **구형 100×100(1만 정점)** — FixMainScene이 에디터에서 만든 구형 (정점간격 20m)
- R2가 TerrainHeightApplier(201×201)를 만들었지만 **씬에 부착되어 있지 않고 런타임 부착 경로도 없음** (가이드 누락)
- 재표본(TerrainTextureApplier)이 새 GetHeightAt을 따라가긴 하나 **1만 정점으론 파장 200m 구릉밖에 안 보임** — 절벽/계곡 디테일 소실
- → **메시 201×201 교체가 이번 수리의 핵심 과제** (씬 YAML 직접 교체는 위험하므로 런타임 경로로)

### 2.4 데코가 점으로만 보이는 것
- 42는 씬뷰 원거리 — Idyllic 나무/바위는 정상 배치됐다면 저해상도에서 점처럼 보이는 게 자연스러움
- 다만 데코 배치가 41 세션의 NRE로 **한 번도 실행된 적이 없었고**(수리됨), 42가 NRE 수리 후 첫 Play 캡처인지 불명 → **재부트 로그 확인 필요**

## 3. 수리 계획 (Phase W1~W4)

### Phase W1. 호수 수면-지형 정합 (근본 재설계) — 최우선

**설계 원칙 전환**: 물이 지형을 따라가지 않는다. 지형이 물에 맞춘다.

1. **호숫가 테라싱(Shore Flattening) 추가** — `TerrainGenerator.ApplyLakeBasins` 확장:
   - 현재: 반경 1.3r 안에서만 depth만큼 파냄
   - 변경: carveRadius를 **2단 구조**로
     - `0.0r~1.0r` (수역): 기존대로 depth 파냄
     - `1.0r~1.45r` (수변 밴드): 지형을 **waterLevel − 0.4m** 로 부드럽게 수렴 (smoothstep) — 호숫가가 항상 수면 아래
     - `1.45r` 밖: 원래 지형 (크로스페이드 15m)
   - 결과: 수면과 지형의 교차가 물리적으로 불가능해짐 → Enforce(물 올리기)가 **발동할 일이 없어짐**
2. **waterLevel 산출 보정**: `baseH - depth + 1.5` 유지하되, waterLevel 결정 후 **호수 주변 링(1.5r) 8방위 기저 높이의 최댓값이 waterLevel+0.5를 넘으면 waterLevel을 max(주변기저) − depth×0.35로 재조정** — 구릉 위의 호수는 자연스럽게 살짝 더 깊어짐 (부유 방지, 결정론)
3. **EnforceSurfaceAboveTerrain은 만반 안전망으로 유지**하되, 새 로그를 WARN→INFO로 강등(정상 경로에서 안 뜨게) + 발동 시 콘솔에 "지형-수면 정합 재확인 요망" 명시
4. 검증:
   - EditMode: 호수 6개 × (중심, 0.5r, 0.9r, 1.2r, 1.4r) 샘플에서 `terrain < waterLevel` 보장 테스트 (역전 0)
   - Play: 전체 맵 씬뷰 캡처(43번) — 호수가 모두 **지면에 눕게** 보이는지

### Phase W2. 지면 머티리얼 영구화 (5번째 재발 차단)

1. `EnsureGroundGrassBaseMap()` 강화:
   - 현재: Resources 경로만 런타임 복구 + 에디터는 #if UNITY_EDITOR 경유
   - 변경: **씬 오브젝트까지 순회** — 씬의 Ground/과태 mesh renderer에 할당된 머티리얼 중 `Ground_Grass` 이름을 가진 것을 찾아(null _BaseMap이면) 런타임에 **인스턴스 복제 + 텍스처 할당** (에셋 파일이 아닌 런타임 머티리얼로 — 에디터 재저장과 무관하게 렌더 보장)
2. 외곽 Ground(평면)에도 동일 가드 적용 — 씬뷰의 어두운 단색 영역 제거
3. 스플랫 머티리얼(Terrain_*_Mat)도 null 가드(스플랫 맵 누락 시 폴백 텍스처)
4. 검증: Play 후 `RenderSettings`/머티리얼 상태 로그 + 44번(근접) 스크린샷

### Phase W3. 지형 메시 201×201 런타임 교체 (굴곡 복원 — 핵심)

1. **GameSetup 부트에 TerrainHeightApplier 런타임 부착 경로 추가**:
   - `EnsureTerrainHeightApplier()`: Ground_Inner에 없으면 AddComponent → Awake에서 GenerateAndApplyTerrain(201×201, 새 GetHeightAt 경로) 실행
   - 순서 보장: TextureApplier(재표본)보다 **먼저** 메시가 201×201이어야 절벽 표현력 확보 — 스크립트 실행 순서 의존 대신, TerrainTextureApplier.Start가 재표본하므로 "메시 교체는 부트 초반, 재표본은 Start" 구조 재확인 후 필요 시 호출 순서 명시

3. 성능: 201×201(4만 정점) — 플레이어 프레임타임 측정(기준 ±3fps)
4. 검증:
