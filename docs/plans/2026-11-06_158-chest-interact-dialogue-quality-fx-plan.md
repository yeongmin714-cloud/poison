## A. 보물상자 상호작용 수리 (원인 확정 포함)

### 원인 진단 (코드 근거)

- `GemChest.OpenInternal()` L104-117: `ContentGate.IsUnlocked("gem_chest", level)` — **게이트 minLevel=10**.
  - Test_21 플레이어는 `CaveInteriorTestSetup.EnsurePlayer()` (L220-233)에서 레벨 세팅 없음 → PlayerStats 기본 Lv1 → **E키 눌러도 조용히 차단**.

- 즉 **로직은 있으나 Lv10 게이트 차단 + 차단 안내가 화면에 안 보임**. (UI 계약 "상호작용불가=피드백 필수" 위반 상태)

### 수리 (P1)
1. **게이트 차단 피드백**: `OpenInternal` 차단 경로에서 `PlayerNotify.Broadcast(ContentGate.GetLockedMessage("gem_chest"))` — 대화 패널 표출("동굴 보석상자는 레벨 10부터 개방합니다"). 게이트 자체는 유지(밸런스 불변).
2. **Test_21 판정 경로**: `CaveInteriorTestSetup.EnsurePlayer()`에서 테스트 씬 한정 `PlayerStats.Level = 10` 세팅 → 영상/Play에서 상자 개방 실동작 판정 가능. (본게임 세이브에는 영향 없음 — Test_21 부트 전용)
3. **OnGUI 💎 [E] 프롬프트 유지** — GLB 치환(147차) 후 루트 불변 계약이므로 로직 무수정, 피드백 경로만 추가.

## B. 플레이어 알림 전면 대화 패널 통일

### 현재 상태
- **이미 대화 패널 경유**: 획득 연출(AcquisitionCinema → OpenForAcquisition), 농경 상태(FarmPlot.FarmStatusBroadcast → ShowTransientMessage [151차 P3]).
- **미연결(화면 안내 누락)**: ContentGate 차단 2곳(GemChest/MercenaryManager — 콘솔만), FishingSystem 물뿌리개 물담기 시작/완료(Debug.Log만), 그 외 ShowStatus류 중 일부.
- 쇼트런 위험: 기존 토스트류(UTKToastService/WarNotificationUTK/TerritoryBannerSystem) 존재 — 전면 대체는 계약 충돌 다발 지대.

### 설계 (P2)
1. **공용 정적 이벤트 버스 신설**: `ProjectName.Systems.PlayerNotify` — `public static event Action<string> Broadcast;` + `Notify(string msg)` 발화자. Systems→UI 단방향 계약(FarmPlot.FarmStatusBroadcast 선례) 준수.
   - `NPCDialoguePanelUTK`가 `PlayerNotify.Broadcast += ShowTransientMessage` 구독([151차 P3] 패턴 그대로 — 3.5s 자동 닫힘, NPC 대화 보호 규칙 유지).
   - FarmStatusBroadcast는 기존 구독 유지(하위호환 — 문구 무변경 계약).
2. **발화점 연결 (1차 편성 — 상호작용 안내/차단 중심)**:
   - GemChest 게이트 차단 → "동굴 보석상자는 레벨 10부터 개방합니다"
   - MercenaryManager 게이트 차단 → 기존 GetLockedMessage 문구
   - FishingSystem: 물담기 시작 "물뿌리개에 물을 담습니다 — 잠시만 기다리세요(2초)" / 완료 "물뿌리개에 물을 가득 담았습니다 (20/20)"
   - ResourceNode/채집·채광: 차단/불가 케이스 존재 시 동일 패턴 연결(구현 중 전수 확인 — 도구/게이트 케이스)
3. **범위 경계 (유지)**: 전쟁 알림(WarNotificationUTK)/영지 배너(TerritoryBannerSystem)는 별도 채널 유지 — 전투/영지 상태는 대화 패널과 별개 톤. 추후 통일 원하면 별도 사이클.

### 검증
- DialogueFeedbackTests 확장: PlayerNotify 버스 존재/구독 계약, GemChest·FishingSystem 발화 소스 어서션.
- 기존 [151차 P3] 계약 문자열 무변경 유지(회귀 0).

## C. 실내 고품질 — 바닥 타일 + 벽면 (P3)

### 기준선(157차 후)
- 바닥: FarmPlotVisuals 흙 단일소스 512² (fbm 음영+균열), 노멀, tiling 0.5(1타일=2m) — **전 층 단일 흙 → 단조가 1차 불만 포인트**
- 벽: fbm 암반 512²+노멀, 얇은 돌 벽 0.5m×3m — 줄눈/층감 없음

### C-1. 바닥 — "흙 + 돌판 경로" 2레이어 (추천안)
1. **돌판 경로 텍스처 신설** (CaveMaterialFactory — 절차 생성, 동굴 전용·농경 흙 단일소스 무손상): 돌 블록 레이아웃(벽돌 오프셋 레이아웃, 3~5열 랜덤 폭, 줄눈 어둡게, 블록별 밝기 ±6%), 512²+노멀(줄눈 깊이 sobel).
2. **경로 셀 도장**: 셀맵 기반 — 스폰(S)→하강 포탈(D)→상승 포탈(U) 최단경로(BFS) 셀 위에 돌판 스티프 오버레이(흙 셀 위 얇은 평면 quad — 바닥 메시 원본 불변, 탑다운 원칙 "바닥원본" 유지). 방 중심(홀)에도 소구역 돌판.
3. **흙 디테일 강화**: 자갈 클러스터(작은 어두운 타원 3~7% 밀도)+밟은 자국 밴드(경로 주변 연하게) — 흙 텍스처는 FarmPlot 공유이므로 **동굴 전용 파생 텍스처로 복제 후 강화**(원본 무변경).
4. 층별 변주: F2+ 습지=이끼 반점(녹색 소량), 유적 테마=돌판 밀도 상향 — CaveLayoutPool 테마 파라미터 연동.

### C-2. 벽면 — 줄눈 돌벽
1. **돌 블록 줄눈 패턴**: 암반 텍스처에 벽돌 레이아웃 오버레이(수평 줄눈 3단/벽 높이, 세로 줄눈 오프셋, 줄눈=어두운 그루브+노멀 깊이) — 512² 유지.
2. **받침 밴드**: 벽 하단 0.4m 어두운 받침(수분/오염 톤) — 컬러 텍스처에 세로 그라데이션 밴드.
3. **이끼/수분 얼룩**: 습지 테마 벽 한정 녹색 얼룩(저주파 fbm 마스크 ×4%).
4. 계약 유지: 벽 런 51(F1)·평면 캡 51·콜라이더 없음(CaveInteriorQualityTests) — **머티리얼/텍스처만 교체, 지오메트리 무수정**.

### 검증
- EditMode: 돌판 텍스처/머티리얼 존재 계약, BFS 경로 도장 셀 수 >0 계약, 벽 51 캡 회귀 0, Dungeon147BTests(얇은 벽/셀 바닥) 회귀 0.
- CaveInteriorQualityTests 텍스처 개수 캡 변화 시 핀 갱신.
