# 실내 바닥·벽 품질 집중 계획서 v2 — 카메라 각도 미세 수정 포함 (2026-11-07)

## 0. 사용자 지시 정리
1. **각도**: 예시 사진과 현재 탑다운이 "미세하게 다르다" — 실측으로 확인하고 살짝만 수정.
2. **가구(보조)**: 색상 테이블 금지 → 원목 톤 테이블/의자만. 테이블 과다 배치 금지.
3. **핵심**: 가구가 아니라 **전체 맵의 바닥과 벽 품질**에 집중한 고품질화 재계획.
4. 계획만 — "진행" 승인 후 실행.

## 1. 실측 결과 (판독 근거)
- **각도**: 예시 사진 = 피치 약 50~60° 쿼터뷰(벽/오브젝트 옆면 노출 화면의 15~20%, 인형의 집, 타일 마름모 눌림).
  현재 실내 카메라 = 명목 65°(IndoorCameraFollow.Pitch const) — 체감상 예시보다 **더 수직**(벽 노출 5~8%, 타일 1:0.42 눌림).
  → 사용자 직감 확정: 각도 차이가 맵 형태 인상 차이의 1차 요인. **살짝 눕히는 방향(65→57°)으로 수정.**
- **바닥 현황**: 전 건물 바닥 = 단일 쿼드 + 256² 절차 텍스처 1장(IndoorTextureGenerator.DEFAULT_SIZE=256).
  성은 예외적으로 좋음(석재 하부 밴드/마모 스탬프/헛짚 데칼 보유). 건물(house/tavern/shop/교회…)은
  텍스처 1장이 방 전체를 무늬 없이 덮음 — 줄눈/마모/방별 차등 없음.
- **벽 현황**: 성 = 석재 하부 밴드+팀버 골조+톱 캡 보유(좋음). 건물 = lower/upper 단색 분할(IndoorMaterialFactory) 또는
  단색 박스(Barn) — 걸레받이/벽톱 캡/벽돌 패턴 없음. 9/20 예시의 투톤+걸레받이+캡 마감이 없는 것이 격차의 본체.
- **가구 현황**: Table/Chair GLB에 채색 변형 포함 + 로비 8세트(사용자: 과다). 원목 톤만 선별 + 수 축소 필요.

## 2. Phase A — 카메라 각도 미세 수정 (살짝만)
- `IndoorCameraFollow.cs` Pitch const **65 → 57** (예시 추정 50~60°의 중간값; 벽 노출 5~8% → 12~15% 목표).
- 영향 범위: 실내 카메라만(실외 PlayerMovement 카메라 무영향). Test_23 관람 모드 90° opt-in은 별도 — 무영향.
- 수동 계약 갱신: `InteriorQualityBaselineTests.T4`(ResolvePitch 기본값 65 핀) → 57 갱신.
  IndoorCameraFollow.Pitch 참조 코드(90° 분기 임계 89.5 등) 무수정 — 기본값만 변경.
- 검증: house/성 실내 캡처 before/after vision 비교(벽 노출율·타일 눌림) + 사용자 Play 체감.

## 3. Phase B — 가구 톤 정리 (보조 — 최소 변경)
- **B1 원목 톤 선별**: Restaurant 팩 Table_2/3/4·Chair_1/2/3 변형별 색을 프리뷰/캡처 판독(vision)으로 분류 →
  원목 톤 변형 접미사만 `InteriorPropCatalog` 시리즈 테이블에 고정(결정론). 채색 변형은 후보에서 제외(소실 금지 — 폴백만 원목).
- **B2 테이블 수 축소**: 성 로비 8세트 → **4세트**(내륀 링만 유지, 외곽 링 제거) + 소파 4→2.
  건물별 1~2세트 유지. 배치 패스 수치만 수정(구조 변경 없음).
- 가구 신규 작업 없음(톤/수량만).

## 4. Phase C — 바닥 품질 (핵심 1)
- **C1 해상도/패턴 상향**: IndoorTextureGenerator 바닥 계열 Generate* — 256→**512**,
  줄눈 명확화(타일 1m 규격 준수 — UV 타일링과 정합), 타일당 톤 편차(해시 스펙클 강화),
  마모 뱅딩(출입문·통로 방향 밝기 감쇠), 균열 스탬프 소량. 기존 톤 팔레트는 유지(퀄리티만 상향).
- **C2 머티리얼 정합**: 성 선례(IndoorMaterialFactory — Smoothness 0.55/노멀맵 균열)를 건물 바닥에 동일 적용.
  노멀맵은 절차 생성(경준선/타일 베벨 — CaveMaterialFactory 선례의 절차 노멀 패턴 승계).
- **C3 건물별 방별 차등**: 방이 2개 이상인 건물(crafthouse 작업구역/매장 구역 등)은 방별 톤 오버레이
  (P1 바닥 오버레이 쿼드 재사용 — 지오메트리 무수정).
- **C4 사용흔적 확장**: 성 AddFloorWearStamps 선례를 건물로 — 문 앞 마모 데칼/통로 뱅딩/난로 주변 그을음.

## 5. Phase D — 벽 품질 (핵심 2)
- **D1 벽 텍스처 상향**: GenerateBrickPattern/StoneWall/PlasterWall/WoodPanel — 512화, 벽돌 오프셋 줄눈,
  얼룩/수분 얼룩 데칼, 하부 어두움 그라데이션(실측 사진 투톤 느낌).
- **D2 걸레받이 밴드 전 건물 확장**: 성 AddWallStoneLowerBands 선례(병합 쿼드 밴드)를
  house/tavern/restaurant/shop/crafthouse/church/barn 전 벽에 추가(높이 0.15m 짙은톤 — 골격 계약 상수 재사용).
- **D3 벽톱 캡 전 건물 확장**: 성 AddWallTopCaps 선례(평면 캡 — 탑다운 바닥 오독 방지 계약)를 전 건물 확장.
- **D4 투톤 배색 정립**: 하단(짙은 톤)+상단(밝은 회반죽) 2분할 유지 — 하단은 걸레받이 톤과 연결, 상단에 미세 얼룩.
- **D5 팀버 골조(선별)**: house/tavern에 성 AddTimberWallFrame 선례 확장(목재 기둥 프레임 — 중세 건축 골조).
  crafthouse/barn은 공장/창고 톤으로 기둥만.
- 지오메트리 무수정 원칙 유지: 밴드/캡/프레임은 **가산 쿼드/박스** — 기존 벽 콜라이더/포탈 계약 무영향.

## 6. Phase E — 검증
- 계약테스트: 각도 기본값 핀 갱신(T4)/원목 시리즈 고정 소스계약/텍스처 512 소스계약/밴드·캡 존재 소스계약(건물별).
- Test_23 관람 모드 전 실내 재촬영 — 바닥/벽 비교 몽타주(기준 사진 옆 나란히 판독).
- 전수 게이트(compile CS 0 + baseline 1:1) + 사용자 Play 판정(각도 체감 포함).

## 7. 실행 순서/방식
- A(각도, 소형) → C(바닥) → D(벽) → B(가구 톤/수량) → E(검증) — 각 단계 위임 구현+부모 게이트,
  600s 타임아웃 시 부모 폴백(관례). Play·커밋 별도 승인.
- 리스크: ①텍스처 재생성으로 기존 색 핀 테스트 이탈 가능(IndoorQualityUpgradeTests H2 등 — 핀 사전 감사) ②각도 변경이
  미니맵/대화 카메라 등 간접 영향 없음 확인(IndoorCameraFollow 소비처 전수 grep) ③500KB급 절차 텍스처 캐시 비용(경미).

## 8. 대기
- "진행" 승인 → A→C→D→B→E 순서로 중단 없이 실행(성→건물 전 실내).
