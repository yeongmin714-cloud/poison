# 🎬 팔(앞다리) 역꺾임 수리 계획 (P-ANIM4, 2026-09-22)

> **기반**: 애니메이션 테스트 8 프레임 분석 — 악어 앞다리 어깨에서 위로 솟아 뒤로 꺾임,
> 미노타우르스 팔 어깨 축 상실·몸 안쪽 말림. (다리 방향은 이전 수리로 정상화됨)

## 진단 (유력 후보 — 실행 첫 단계에서 코드로 확정)
1. **미노타우르스 팔**: 2족 컨트롤러의 팔 스윙이 본 로컬 축을 가정한 직접 회전 — 익명 리그의
   임의 축에서 스윙 평면이 임의 방향(몸 안쪽/뒤쪽)으로 풀림. 다리가 FromToRotation 델타로
   수리된 것과 동일한 부류의 문제.
2. **악어 앞다리**: ①앞/뒤 판정이 리그 forward와 반대(전/후 스왑 — 뒷다리 굽힘 로직이 앞다리에) 가능성
   ②앞다리 pole 힌트가 hind 재사용(LF_Hint/RF_Hint 재사용)이라 방향 부적합.
3. **매핑 오분류 가능성**: 미노타우르스 팔 후보에 뿔/목 체인이 잡혔을 가능성(팔 조건 부족).

## Phase 1 — 진단 로그 강화 (30분)
- 매핑 로그에 각 역할 배치 상세 출력: `L_Hip=bone_16(3뼈) R_Hip=... L_Hind=... 팔: Shoulder=...`
- 4족/2족 전/후 판정값(z 평균) 출력 → 악어 전/후 반전 여부 즉시 확인

## Phase 2 — 악어 앞다리 역꺾임 수리
- **전/후 판정 안전화**: z 평균이 ±0.02 이내로 붙으면(판정 불능) → 양쪽 다리를 모두 "앞다리 역할"
  로 배치(뒷다리 Hind 미배치 = 기존 폴백 경로) — 파충류처럼 다리 위치가 중앙에 몰린 리그 대응
- **앞다리 전용 힌트**: 앞다리(L_Hip/R_Hip 체인) Solve 시 pole 힌트를 체인 실제 진행방향에서 산출
  (hind 재사용 제거), 굽힘 반대로 나오면 bendSign 플립
- 완료 기준: 악어 앞다리가 아래로 내려와 정방향으로 굽힘

## Phase 3 — 미노타우르스 팔 수리
- **팔 스윙 델타화**: 2족 팔 스윙의 직접 회전을 "현재 시각 방향→목표 방향" 델타 방식으로 교체
  (다리 수리와 동일 패턴 — LimbIKSolver.FromToRotation 재사용)
- **팔 후보 필터 강화**: 팔 = 다리가 아닌 체인 중 **아래로 뻗지 않고(위/옆) root에서 가까운** 체인
  (뿔/목 오배치 방지). 판정 불능 시 팔 역할 미배치(자연 폴백 자세 유지)
- 완료 기준: 미노타우르스 팔이 몸 옆으로 자연스럽게 내려와 스윙

## Phase 4 — 검증
- 영상 재촬영 비교 + 텔레그램
- 확인 로그: Phase 1 상세 매핑 로그, ShowcaseMonitor 폴백 경고 유무

## 진행 규칙
- Phase별 커밋 · CS=0 + EditMode · QAPROGRESS 기록 · 텔레그램
- Solve/컨트롤러 수정은 메인 씬 몬스터에도 영향 — 회귀 점검 포함
