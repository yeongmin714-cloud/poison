# 🎬 다리 역굽힘(뒤로 꺾임) 수리 계획 (P-ANIM3, 2026-09-22)

> **상황**: 애니메이션 테스트 5 — 무릎 힌트를 앞쪽(forward)으로 바꿨음에도 **다리가 여전히 뒤로 꺾여 걸음**.
> **상태**: 계획 확정 — "진행" 시 Phase 순차 실행

## 진단 (현재 확정된 사실 + 유력 가설)
1. **힌트 변경이 무효였다** → LimbIKSolver.Solve가 hint를 실제 굽힘 방향에 쓰지 않거나(미사용/조건부),
   또는 굽힘 평면이 힌트가 아니라 **본 자체 로컬 축**에서 결정되고 있을 가능성이 최우선.
2. **체인 재정렬 이슈**: 토폴로지 매핑이 chain[0]=위(엉덩이)→chain[끝]=잎(발)로 배치했으나,
   Solve가 뼈의 로컬 +Y/+Z 기준으로 삼각형을 풀기 때문에 익명 리그의 로컬 축 방향에 따라
   굽힘 쪽이 반대로 나올 수 있음(이름 없는 뼈는 축 규약이 없음).
3. **원인 확정 방법**: Solve 본문(~407줄)을 읽어 hint 사용처와 굽힘 평면 결정 로직을 코드로 확정 + 한 몬스터(늑대)에
   굽힘 방향 강제 플래그 테스트.

## Phase 1 — Solve 굽힘 방향 근본 수리 (핵심)
- LimbIKSolver.Solve 본문 분석: hint가 굽힘 평면에 실제 사용되는지 확인
- **굽힘 방향 명시 파라미터 추가**: `Solve(chain, target, hint, bendSign)` — bendSign=+1이면
  루트→타깃 방향에서 오른쪽(또는 진행방향)으로 중간 관절이 굽고, -1이면 반대
- 4족/2족 호출부에서 bendSign = +1(앞다리 정방향) 지정 — 결과가 반대면 -1(데이터로 확인)
- 완료 기준: 모든 다리가 진행 방향으로 굽힌 보행(뒤로 꺾임 0)

## Phase 2 — 보행 품질 (P-ANIM2 Phase A/B 이월)
- 골반 체중이동(y 진폭+좌우 롤), 스트라이드-속도 동기(발 미끄러짐 제거), 머리 바운스/체간 롤
- (P-ANIM2 계획서와 동일 — 다리 방향 수리 후에 튜닝해야 의미 있음)

## Phase 3 — 접지감 (블롭 섀도우) + 라벨 방해 제거
