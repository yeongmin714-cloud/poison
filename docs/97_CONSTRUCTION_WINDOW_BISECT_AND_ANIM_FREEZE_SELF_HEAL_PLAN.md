# 97차 스펙(개정) — 믹사모 클립 루프 미설정(전원 애니 프리징의 단일 뿌리)/카메라 대화 수명 연동/F키 프롬프트 즉시 부착/U키 바이섹트

> 발행: 감독자 (2026-10-16 개정). 근거: 마을씬 테스트 8 + Editor.log(23:37 세션) + **FBX .meta 전수 실측**. **계획만 — 구현 별도 승인.**
> 사용자 보고: ①모든 NPC 애니 이상(다리 안 움직임/상체 고정) ②카메라는 대화가 끝날 때까지 NPC를 비춰라 ③상호작용 프롬프트 NPC 대상 앞 즉시 부착(전 계획 누락 — 재반영) ④U키 발현 안 됨.

## 결함 1 — [핵심 발견] 믹사모 클립 루프 미설정 = 전원 애니 프리징의 단일 뿌리
- **결정적 증거(.meta 전수 실측)**: Villagers_Mixamo/{Walking,Idle}.fbx.meta + Combat_Mixamo/{Block,Slash}.fbx.meta **전부 `clipAnimations: []`(빈 배열)** — 클립별 임포트 설정이 없음 = `m_LoopTime` 기본값 0 = **클립 1회 재생 후 마지막 프레임 정지**.
- **증상 완전 해명**: 걷기 1사이클(≈1.1s)만 재생되고 포즈가 그 지점에 얼음 → VillagerWanderer는 계속 이동 → "다리가 안 움직이고 상체 고정+미끄러짐". **모든 주민이 동일 클립을 쓰므로 전원 증상 동일** — 사용자 보고("모든 npc가 이상해")와 정확히 일치.
- **왜 이제 발견됐나(셀프 감사)**: 이전 판정들의 프레임 샘플링이 스폰 직후 첫 사이클(2~8s 창)에 몰려 있어 정상 걷기만 봤음 — 루프 종료 이후(스폰 ~1.1s 뒤)가 결함 구간. 이후 판정은 **최소 10s 경과 후 샘플**로 통일.
- **수리(에디터 배치 스크립트 — .meta 수기 편집 금지)**:
  1. 에디터 스크립트(Assets/Editor/Tools/)+batchmode `-executeMethod` 실행: ModelImporter 경유 — `defaultClipAnimations` 팝업 → 각 항목 `loopTime = true` → `clipAnimations` 재할당 → `SaveAndReimport()`. 대상: **Villagers_Mixamo/{Walking,Idle}**(루프 필수). Combat_Mixamo/{Block,Slash}은 원샷 유지(루프 불필요 — Block은 창 유지 모션, Slash은 반격 1회 — CrossFade 복원 계약과 일치). [97차 F1] 마커.
  2. **검증(자동)**: 재임포트 후 .meta에 `m_LoopTime: 1` 존재 실측 + EditMode에서 `AnimationClip.isLooping` 실측 테스트(리소스 로드). [97차 F1] 마커.
  3. **검증(Play)**: 주민이 걷기를 **10초 이상 연속** 유지(루프 반복)+idle 호흡 지속 — 이전 판정 기준(짧은 창) 폐기.

## 결함 2 — 대화 카메라: "대화가 끝나기까지 NPC를 비추게"(사용자 지시) — 카메라 수명을 대화 패널에 연동
- **현황**: 세션이 5s 타이머/이동키로 종료됨 — **대화창이 아직 열려 있는데 카메라가 복원** → 복구된 오빗에서 플레이어가 크게 보임(사용자 체감 "카메라가 플레이어를 봄"의 실체).
- **수리**:
  1. 주민 경로(fullBody=true): 종료 조건을 **NPCDialoguePanelUTK 패널 수명에 연동** — Director 틱에서 `패널이 닫혔으면 End`(폴링 — 기존 틱에 추가). 5s 타이머 폐기, **이동키 종료 폐기**(대화창 열림 중 이동 무시 — 패널이 입력 게이트), ESC만 수동 종료 유지. [97차 F2] 마커.
  2. 병사/영주 경로(fullBody=false)는 기존 계약 유지(73차 — 타이머/이동 종료 무변경).
  3. 안전: 패널 이벤트 없이 닫히는 경로(대상 사망/파괴) 기존 감시 유지 — End 멱등.
  4. 테스트: 패널 닫힘→End 호출, 패널 열림 유지→이동키로 미종료 어서션(소스+로직). [97차 F2] 마커.
- 실측 보증: 영상8 실측상 세션 중 클로즈업은 정상 렌더(타일 1~4·10~12 — 플레이어 0%) — 본 수리는 "세션 종료가 이르다"를 고치는 것.

## 결함 3 — F키 상호작용 프롬프트: NPC 대상 바로 앞 즉시 부착(전 계획 누락 — 재반영)
- **요구**: F키 → 패널/프롬프트가 NPC **바로 앞**에 즉시 부착.
- **현황 실측**: 94차 F4로 정면 앵커(FrontOffset 0.6m)+개방 프레임 즉시 1회 배치는 구현됨 — 그러나 영상8에서 체감상 부착 실패로 보이는 순간이 있었음 → **개방 순간 배치 로그와 NPC 화면좌표 대조가 이번 검증 핵심**.
- **수리**:
  1. **개방 프레임 배치 보장 강화**: OpenForTarget → PlaceAtTarget 즉시 1회(기존) + **다음 프레임 재배치**(레이아웃 확정 후 보정 — 1회) — 개방 첫 프레임 레이아웃 미확정으로 중앙 폴백처럼 보였던 순간 제거. [97차 F3] 마커.
  2. **부착 검증 로그**: 배치 시 패널 worldBound와 NPC screenPx 같이 로그 — 부착 실패 체감 시 즉격. [97차 F3] 마커.
  3. F4 정지(94차)+재개 전수화(96차) 계약 유지.
- 테스트: 개방 프레임+다음 프레임 2회 배치 어서션. [97차 F3] 마커.

## 결함 4 — U키 건설창 미렌더: 바이섹트(마젠타)+UIDocument 전수 진단 (전 계획 유지)

- **바이섹트**:

  2. **UIDocument 전수 진단**: 씬의 모든 UIDocument(이름/패널 크기/sortingOrder/enabled)+창 소속 패널 대조 로그 — 이중 부트 확정. [97차 F4] 마커.

  4. 유저 협조: 재현 시 Window > UI Toolkit > Debugger에서 "UTKWindow_건설 관리" 선택 캡처.
  5. 마젠타 진단은 임시 — 원인 확정 후 제거(별도 승인).
