## 수리 항목 (검증 기준 사전 정의)

### F1. 병사 크기 — 추정 금지, 실측 우선
- **선례 교정 실측**: 가드(SkeletonGuardPlaceholder)는 무스케일 스폰이고 월드 실측 1.8m(87차) → soldier GLB 원본이
  1.8m일 가능성이 있다. RT의 "점 수준"은 **수직 관전의 자연 투영**(1.8m 인간을 정수직에서 보면 좌우 0.5m)일 수 있어
  크기 결함과 투영 문제가 겹쳐 있다.
- **수리(측정 먼저)**: pit_late 덤프에 **결투선수 렌더러 bounds(월드 높이) 덤프** 추가 → 다음 Play에서 실측 높이 확정.
  - 실측 < 1.5m → TerritoryBuilder/CreateGuard 계열의 검증된 1.8m 패턴 이식(선례 코드 복사만).
  - 실측 ≥ 1.5m → 크기는 정상 — **가시성은 식별 수단(이름표+애니+위치)으로 해결**(아래 F3/F6).
- **판정 기준**: 실측 높이 수치 보고 후 분기 수리 — 추정 금지.

### F2. 플레이어 관전 배치 — 시야 내 고정
- pit 진입 시 플레이어 **(0, 0.65, -7.5)** 로 배치(모래 남측 가장자리, 관전 뷰 내부 z±8/x±14.2) —
  기존 (0,0.5,-18)은 뷰 밖.
- R-B 이동 차단 유지 → 결투 내내 그 자리 고정(사용자는 자기 캐릭터를 보며 관전).
- **판정 기준**: 영상/RT에서 플레이어 모델이 화면 하단부에 상시 표시.

### F3. 이름표 보장
- pit 진입 시 `NameplateOverlayUTK.Ensure()` 명시 호출(부트스트랩 의존 제거) — 이미 존재면 멱등.
- pit_late 덤프에 오버레이 존재 여부 추가(FindObjectOfType<NameplateOverlayUTK>).
- **판정 기준**: 재Play 영상에서 병사 2명 위에 이름+HP바 표시(스크린스페이스 — RT 불가, 영상으로 판독).

### F4. 카메라 기록자 전원 게이트 — DialogueCameraDirector 포함
- ReframeCamera/End-복원/전체 카메라 기록 경로에 `ArenaSpectatorCameraLock.Active` 게이트 추가 —
  **카메라 transform.position을 기록하는 모든 Systems 코드가 게이트를 통과하도록** (누락 시 락 2차 방어가 흡수).
- **판정 기준**: 재Play에서 [ArenaSpectatorLock] 이동자 감지 로그 **0건** — 0건이면 락 없이도 정상(근본 수리 완료).

### F5. 진단 신뢰성 수리 — RT 캡처 타이밍
- CaptureRenderTarget 직전에 카메라를 관전 프레이밍으로 강제 세팅 후 Render →
  캡처 = 실제 사용자 뷰(Update 이동자의 중간 상태 오염 제거 — 이번 RT 검정 아티팩트 재발 방지).

### F6. 결투 스폰 타이밍 관측
- 영상12의 아레나 구간(6s+2s)이 스폰 대기 창과 겹쳐 "병사 없음"이 자연 결과였을 가능성 —
  pit_late 덤프에 결투선수 존재(태그 개수/이름/위치/bounds) 명시 → 스폰 시점-가시성 분리 확정.
- **판정 기준**: 스폰은 정상(로그 실측됨) — 문제는 "언제 보이는가"와 "얼마나 보이는가"로 분리 보고.

## 검증 절차 (재Play 1회)
1. RT 판독(pit + pit_late): 전체 아레나 + 병사 1.8m 2기(11% 높이) + 플레이어 하단 표시
2. 영상(사용자) 판독: 이름표 2개(이름+HP바) + 병사 애니 + 결투 진행
3. 로그: 이동자 감지 0건 / 예외 0 / baseline 1:1
4. 미충족 시: 충족 안 된 판정 기준을 명시하고 동일 절차 재수리(임시방편 금지)
