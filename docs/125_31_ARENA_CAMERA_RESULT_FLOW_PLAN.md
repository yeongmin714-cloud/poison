## 사용자 의도 확인 (이해 확인)

1. **카메라**: 아레나 전투 카메라가 너무 수직(탑다운)이라 생동감이 없다 → 카메라를 낮춰/기울여 사선 관전으로 전투를 입체적으로.

3. **버그 보고**: 방금 Play에서 승리/패배 UI가 뜨지 않았다 → 원인 진단 필수.

→ 세 가지 모두 확인했으며, 아래 실측으로 3번의 원인까지 수치로 확정했다.

## 수리 항목 (판정 기준 사전 정의)

### M1. 관전 카메라 사선화 — 수직 90° → 사선 62°
- 대상 2곳(같은 프레이밍 계약): ①ArenaSpectatorCameraLock — Attach 초기화+프레임 말 복원(L82-83) ②RenderAuditProbe F5 캡처 직전 강제(캡처=사용자 뷰 계약 동기).
- 수치: `(0,26,0)+Euler(90,0,0)` → **`(0,17.8,-8.9)+Euler(62,0,0)`** — 시선축이 격투 중심(0,1,0)을 통과하는 정합 배치(고도 62°). orthoSize 8→**10**(사선 투영에서 전투원+주변 지형 동시 수용 — Play에서 미세조정).
- 가림 기하 검증(완료): 카메라 z=-8.9는 외곽 벽(z=±23.9) 안쪽 — 남벽은 카메라 뒤, 북벽은 시야 지면 도달점(z≈+0.5) 뒤라 **벽 가림 없음**.
- 관전 휠줌 계약 유지(휠 ortho 줌 min 6/최대 기존값 — 락 ortho 강제 없음 계약(후속25 R4) 그대로).
- **판정**: 재Play 영상에서 병사 측면/무기 궤적이 보이는 사선 시야 + 벽/지형 가림 0.

### M2. 결과 흐름 재구성 — "투기장 내 결과창 → 확인 → 로비 복귀"
- 현행: 종료 → 유예 2.5s → 선수 파괴 → 로비 복귀(EnterBuilding) → 로비 폴링 → OnResultReady → 결과창(로비에서).
- **변경**: 종료 → 유예 2.5s(패자 다운 관람 — 이 시간에 다운이 보임) → **선수 파괴 없이 투기장에서 OnResultReady 발화** → ArenaResultWindowUTK 표시(풀스크린 — 배경은 아레나) → 사용자 **확인/Enter/Esc** → `ArenaBettingSystem.ReturnToLobbyAfterResult()` 신설(선수 파괴+상태 정리+EnterBuilding(TYPE_ARENA)) → 로비.
- 기존 K6의 로비 준비 폴링/로비 발화 코드는 폐기(이벤트 발화 시점이 투기장 내로 이동 — 코루틴은 발화 직후 종료, 이후 흐름은 창 콜백이 소유).
- **_duelRunning=true 유지** 확인까지 — 결과 표시 중 베팅창 재개방 차단(확인 시 false).
- **폴백 사슬(고립 금지)**: ①Open 시 UIRoot null → 토스트 안내+1s 간격 3회 재시도 ②그래도 실패 → ArenaBettingSystem 폴백 코루틴(발화 후 12s 내 표시 확인(Ack) 없으면 자동 로비 복귀).
- **판정**: 재Play에서 ①패자 다운이 화면에 보이는 구간 존재 ②투기장 배경 위 결과창 표시 ③확인 입력 후에만 로비 전환.

### M3. 결과창 NRE 수리 + 안전망 (이번 사고의 구조적 교훈)
- **근본 수리**: BuildPanelTitle이 제목/보조 라벨 참조를 저장(_mainTitle/_mainSub 할당) — 우판 보조 제목은 승/패 문구 분기("승리 베팅 정산"/"패배 베팅 정산")라 참조 필수. 좌판은 고정 문구.
- **안전망(계약화)**: Open 전역 try-catch — UI 결함이 게임 코루틴을 죽이는 구조 폐기(이번 NRE의 실측 교훈). catch 시 로그+폴백 복귀 트리거(M2 폴백 사슬).
- **이벤트 역전 방지**: ArenaBettingSystem의 OnResultReady 발화 로그를 Invoke 이전으로 이동+Invoke try-catch — 구독자 예외가 듀엔 종료 로그를 삼키지 않게.
- **M3-부수**: 로비 관리인 NPC T포즈 여부 재확인(영상14 f_002) — 증상 확인 시 별도 승인으로 수리(애니 패리티 계약 적용 대상 판정).
