## 포렌식 확정 (마을씬 테스트 5 — Test_15 마을씬, 게임 t 1.4~69.6)

### 결함 1 — 대화 카메라: 게이트 성공(줌인 도달) + 방향 이동 잔존 → "대상 고정"으로 완성
- **성공 확인(93차 F1 유효)**: 영상 35.8~41.8s — 타일 9에서 **NPC 전신 정면 근접 클로즈업 실제 렌더**(역대 최초). Begin 로그 pos=(-439.6,3.2,-78.7) boundsY=1.81 정상. 게이트가 프레이밍을 화면까지 도달시킴.
- **잔존 결함**: 타일 7~8(전환)/10~12(세션 중)에서 NPC가 측면/등으로 보임 — "카메라 방향 이상". 원인: ①ReframeCamera가 현재 위치 기준 dir 재투영(고정 베어링 아님) ②fullBody 경로의 90° 클립 회전 잔존(발생 근거 없음 — 방향 이상 요인) ③카메라 우선권이 Director Update라 추격 스크립트와 타이밍 경합 여지.
- **사용자 요구 = 대상 고정 카메라**: "말을 건 대상에게 카메라를 고정시켜 그 대상만 보게" — 이것이 정답이며 구현 경로가 명확하다.
- **수리**:
  1. **고정 베어링 프레이밍**: Begin에서 베어링 확정(플레이어→대상 방향 = NPC 정면 — NPC 응시 회전과 일치) 후 세션 내 유지. 카메라 = 대상 center + 베어링×2.92m, 높이 = center+1.2m(약상반 → 하단에 플레이어 머리 최소화), LookAt = 대상 center. [94차 F1] 마커.
  2. **ReframeCamera 단순화**: fullBody 경로 dir 재투영 폐기 → 고정 베어링+고정 오프셋 유지 + 매 프레임 LookAt 갱신(대상 이동 추적 — "고정시켜 그 대상만 보게"). 90° 클립 회전 폐기(fullBody 한정 — 병사 경로 무변경). [94차 F1] 마커.
  3. **최종 적용권 이전(이중 안전)**: Director Ensure 업데이터를 Update→LateUpdate로 전환 — PlayerMovement(93차 게이트 유지)보다 나중에 실행되어 어떤 추격자도 프레이밍을 덮어쓸 수 없음. [94차 F1] 마커.
  4. End 원복 유지(93차 계약).

### 결함 2 — U키 건설창 미표시: 부착·레이아웃·온스크린 전부 정상인데 렌더 부재 → DOM 격리 단계로
- **증거(이번 세션 신규)**: 열림 로그 3회 사이클(59.9 개방→62.2 닫힘→62.4 개방→69.6 닫힘 — 유저가 못 봐서 반복 토글한 흔적). `개방 직후 화면 상태 — panel=(1440x909) k=0.750 windowRect=(120,65,1200x780) onScreen=True` — **레이아웃 완전 정상**. 영상 56.9~66.6s(개방 구간)에서 창 렌더 전무 + 화면 생존(카메라 추적·다른 UI 렌더 정상).
- **결론**: 좌표/스케일 문제 아님 — **요소가 그려지지 않는 것**(가림/죽은 패널/시각 리소스 누락 계열). 유력 후보 2:
  1. **ThemeUss 배경 누락 연관**: baseline 실패 항목 `ThemeUss_HasBakedBackgroundPngs`(테마 USS 배경 PNG 누락) — 창 패널 시각이 USS 배경 의존이면 누락 시 투명 패널+밝은 초록 필드 위 저대비 → 사실상 안 보임.
  2. **가림/죽은 패널 부착**: 형제 z-순서/다른 패널(UIDocument) 부착.
- **수리**:
  1. **코드 배경 폴백(무해·즉효)**: 창 패널들에 USS 배경 대신 단색+보더 인라인 스타일 폴백(Figma 톤: 다크 패널 #1B1F27/0.92+보더) — 배경 리소스 누락과 무관하게 항상 보임. [94차 F2] 마커.
  2. **DOM 진단 로그**: 개방 시 조상 체인 실측(패널 이름/자식 인덱스/형제 수/display·visibility·opacity/pickingMode) — 가림·죽은 패널 즉격. [94차 F2] 마커.
  3. **유저 협조**: 재현 시 에디터 Window > UI Toolkit > Debugger에서 창 요소 선택 화면 캡처(있으면 원인 1회 확정).
- 유저 환경(Interaction Mode = No Throttling) — 에디터 스로틀 설 배제됨. Play Focused는 Game 뷰 툴바 좌측 드롭옆 체크/버튼(다음 확인 요청 — 이번엔 불필요할 수 있음: 화면 생존이 실측됨).

### 결함 3 — 애니: 스트라이드 캘리브레이션 실패 수리(93차 F3 미작동 원인)
- **증거**: `스트라이드 정합 — model=... animSpeed=1.00 (폴백 — 실측 실패: 발 본=있음 샘플 8/7)` 전 주민 동일 — **샘플 10 미달로 전량 폴백**, 보정 미작동이 "여전히 미끄러짐"의 주원인.
- **수리**: 요건 완화(샘플 ≥5)+관측 윈도우 2.5→3.5s+걷기 재진입 시 재시도 유지 — 로그로 animSpeed 실반영 확인. [94차 F3] 마커. (영상 판정 A- — 이 외 이상 요소는 재영상 지정 시 추적)

### 결함 4 — F키 상호작용: 대상 NPC 즉시 정지 + 상호작용 프롬프트 NPC 바로 앞 즉시 부착 (사용자 추가 요구)
- **요구**: F키를 누르면 ①대상 NPC가 이동을 정지하고 ②상호작용 패널이 NPC **바로 앞**에 즉시 부착.
- **현황**: F키 패널 개방 시점엔 NPC가 배회 지속(정지는 '대화하기' 클릭 시점에만 — PauseForDialogue 89차) → 패널이 움직는 NPC를 따라다니고, 개방 직후 프레임에서 프롬프트가 대상에 미부착일 수 있음.
- **수리**:
  1. **F키 개방 즉시 정지**: F키로 상호작용 패널이 열리는 시점(InteractionPanelUTK.Open/OpenForTarget — 주민/마을NPC 대상)에 대상 배회 정지 API 호출 — 주민=VillagerWanderer.PauseForDialogue 재사용(대화하기 클릭 전체 경로와 중복 호출 무해·멱등), 마을NPC=기존 정지 API(TerritoryNPCBehaviour 계열). 패널 닫힘/대상 변경 시 ResumeAfterDialogue 재개. [94차 F4] 마커.
  2. **바로 앞 앵커**: 프롬프트/패널 앵커 = NPC **정면 발 앞** — `bounds center + NPC.forward×FrontOffset(0.6m)`, 높이는 기존 클램프(1.2~2.2m) 유지 — NPC가 정지 상태라 프롬프트가 흔들리지 않음. 개방 프레임 즉시 PlaceAtTarget 1회 + PlacementTick 유지. [94차 F4] 마커.
  3. 정지 유지 계약: 대화 진입 시 기존 흐름 무변경(이미 정지 상태에서 Pause 재호출 무해).
