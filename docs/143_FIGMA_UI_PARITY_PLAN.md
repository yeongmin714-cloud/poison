## §2 감사 방법 — 1:1 비교 프로토콜 (창 단위)

1. **Figma 측**: REST API(GET files/:key/nodes)로 해당 프레임 재실측 → 레이아웃 트리(프레임/그룹/텍스트/그리드) + 절대좌표/크기/폰트(크기·굵기)/색/투명도/radius 추출 → `docs/figma_truth_143/<창명>.json` 스냅샷.
2. **게임 측**: 해당 UTK 클래스의 좌표/크기/폰트/색 상수 열수 + Play 스크린샷(Figma와 동일 해상도 1920×1080) 캡처.
3. **비교 축(사용자 지정 5축)**: ①그리드(칸 수·간격·정렬) ②배열(요소 순서/위치) ③여백(padding/margin) ④플루언트 스타일(배경 투명도/글래스/그림자 유무 — Figma가 진실) ⑤폰트크기.
4. **판정 기록**: 창별 불일치 표(요소별 Figma치 vs 현재치) → `docs/143_figma_parity_audit.md`에 누적.

## §3 수정 원칙

- **Figma가 단일 진실** — 게임이 맞춘다(역방향 금지). 다만 Figma에 없는 신규 요소는 사용자 승인 후 Figma에 역반영 제안.
- **플루언트 계약**: 창 배경은 Figma 지정 투명도/글래스만 유지 — 임의 고체판 금지. 단, 상호작용 패널처럼 사용자가 "피그마 스타일이 낫다" 재판정한 창은 그 판정이 최우선(142차 B 원복 선례).
- **그리드/폰트 상수는 단일소스**: 창별 하드코딩 수치 → 해당 창 상수 블록 상단 집중(정합 수정 시 한 곳만).
- 1창 = 1사이클(수정→컴파일 0→스크린샷 픽셀 비교→사용자 확인) — 대량 일괄 수정 금지(사용자 승인 리듬 계약).
