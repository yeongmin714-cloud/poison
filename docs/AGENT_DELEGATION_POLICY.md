# 🧭 에이전트 위임 정책 (Agent Delegation Policy) — 필수 준수

> **효력:** 이 문서는 본 프로젝트에서 동작하는 모든 AI 에이전트(감독자/오케스트레이터 및 하위 서브에이전트)에 대해 **강제 규칙**이다. 이 정책을 위반한 작업물·보고서는 무효로 간주하며, 재작업 대상이 된다.
> **핵심 원칙:** 감독자(director/orchestrator)는 **생각하고 지시하고 검증하는 역할**만 한다. 코드 작성과 QA 실행은 **반드시 서브에이전트에게 위임**한다. 감독자가 직접 코드를 고치거나 직접 테스트를 돌려서 나온 판정은 **증거로 인정되지 않는다**.
> 제정: 2026-10-12 / 문서 위치: `docs/AGENT_DELEGATION_POLICY.md`

---

## 1. 역할 정의

| 역할 | 담당 | 성격 |
|:--|:--|:--|
| **감독자 (Director/Orchestrator)** | 사용자와 직접 대화하는 상위 에이전트 | 계획·위임·검증·보고. **실행(코딩/QA) 불가** |
| **구현 서브에이전트 (Implementation Subagent)** | 감독자가 생성/위임한 하위 에이전트 | 게임플레이 코드·테스트 코드 작성 및 컴파일 확인 실행 |
| **QA 서브에이전트 (QA Subagent)** | 구현과 **별개**로 위임된 하위 에이전트 | 컴파일/EditMode/Play 검증 실행 및 증거 수집 |

- 구현과 QA는 **서로 다른 서브에이전트**로 분리한다. 같은 서브에이전트가 "내가 짠 코드는 내가 검증했다" 형태로 자기검증(QA 겸직)하는 것은 원칙적으로 금지하며, 부득이하게 단일 서브에이전트 환경에서만 실행될 때는 보고서에 `QA 겸직: 예 (위임 불가 사유: …)`를 명시하고 사용자 승인을 받아야 한다.

## 2. 감독자에게 허용되는 행위 (Allow List)

감독자는 아래 행위만 수행한다.

1. **발견(Discovery):** 코드베이스/문서/로그를 **읽고** 현황을 파악 (읽기 전용).
2. **범위 지정(Scoping):** 이번 작업에서 건드릴 파일·시스템을 명시한 **범위 목록(scope files)** 작성.
3. **계획(Planning):** Phase/사이클 단위 작업 계획 수립.
4. **스펙 문서 작성:** `docs/` 아래 계획·스펙·정책 문서 작성 (마크다운 문서는 감독자가 직접 작성 가능 — 단, 게임플레이/테스트 코드는 예외 없음).
5. **위임(Delegation):** 서브에이전트에게 구현·QA 태스크 발행 (범위 파일, 완료 기준, 증거 요건 포함).
6. **검토(Review):** 서브에이전트가 제출한 **diff, 파일 경로, 테스트 증거(로그/리포트 파일)** 를 읽고 대조·검증.
7. **조정(Reconciliation):** 증거 간 모순 발견 시 재위임 또는 사용자에게 보고.
8. **최종 보고(Final Report):** 사용자에게 결과 요약, 남은 위험, 다음 단계 제안.

> 감독자의 검토는 **산출물 증거 기반**이다. 감독자가 직접 실행한 결과가 아니라, 서브에이전트가 남긴 **파일·diff·로그**를 읽고 판정한다.

---

## 3. 감독자 금지 행위 (Deny List — 하드 금지)

아래 행위는 **예외 없이 금지**다. "간단한 수정이라서", "위임이 늦어서", "확인차 그냥 돌려봤다"는 모두 변명이 될 수 없다.

1. ❌ **게임플레이 코드 직접 편집** — `Assets/` 아래 런타임 스크립트(MonoBehaviour, 시스템 클래스 등)를 감독자가 직접 수정·생성·삭제 금지.
2. ❌ **테스트 코드 직접 편집** — `Tests/`(EditMode/PlayMode) 관련 스크립트 직접 수정 금지.
3. ❌ **프로젝트 파일 기타 직접 조작 금지** — 어셈블리 정의(`.asmdef`), 프리팹/에셋 파일, 에디터 스크립트(`-executeMethod` 배선용 포함)도 서브에이전트 소관. 감독자 직접 수정 금지.
4. ❌ **QA/빌드/테스트 실행 금지** — Unity 컴파일 실행, EditMode 테스트, Play 모드 검증, 빌드, `-executeMethod` 실행 등을 감독자가 직접 수행 금지.
5. ❌ **자기 실행 기반 판정 금지** — 감독자가 직접 돌린 결과로 "컴파일 통과", "테스트 성공", "QA 완료" 등의 판정을 내리고 보고하는 것 금지. QA 판정의 유일한 근거는 **QA 서브에이전트의 증거물**이다.
6. ❌ **침묵 인계 금지** — 위임 실패/서브에이전트 부재 시, 사용자 승인 없이 감독자가 몰래 작업을 대행하는 것 금지 (§7 참조).
7. ❌ **증거 없는 보고 금지** — "완료했다", "QA 통과했다"를 diff/로그 경로 없이 보고하는 것 금지.

## 4. 표준 위임 워크플로 (모든 코드 태스크에 필수)

```
[감독자] 발견 → 범위(scope files) 지정 → 계획/스펙 문서 작성
   ↓
[감독자 → 구현 서브에이전트] 위임: 스펙+범위 파일 목록+완료 기준 전달
   ↓
[구현 서브에이전트] 코드 작성 → 컴파일 확인 실행 → diff/경로/컴파일 증거 제출
   ↓
[감독자] diff·경로 검토 (읽기 전용) — 사양 일치, 범위 이탈 여부 확인
   ↓
[감독자 → QA 서브에이전트] 위임: 검증 항목(컴파일/EditMode/Play 구분) 전달
   ↓
[QA 서브에이전트] 검증 실행 → 증거물(로그 파일/테스트 리포트 경로) 제출
   ↓
[감독자] 증거 대조·조정 → 최종 보고 (사용자 승인 게이트 안내 포함)
```

**필수 규칙:**
- 모든 코드 태스크는 **반드시** 구현 서브에이전트에게 위임한다 (§3-1~3).
- QA는 구현 완료·diff 제출 **이후에** 별도 서브에이전트에게 위임한다. 구현 전 QA 위임은 무의미하며, 구현 서브에이전트의 "자기 판정"으로 QA를 대체하는 것도 금지.
- 위임 시 감독자는 최소한 다음을 서브에이전트에 전달해야 한다:
  - 범위 파일 목록 (수정 가능한 파일의 화이트리스트)
  - 완료 기준 (무엇을 만족해야 끝인가)
  - 증거 요건 (어떤 경로·형식으로 제출할 것인가 — §5)
  - 이 정책 문서 경로(`docs/AGENT_DELEGATION_POLICY.md`) — 서브에이전트도 본 정책을 준수한다.

## 5. 서브에이전트 산출물 요건 (증거 표준)

### 5-1. 구현 서브에이전트 제출물 (전부 필수)
- **수정 파일 경로 목록** — 절대/상대 경로 전체.
- **diff** — 파일별 변경 전후 (또는 감독자가 읽을 수 있는 diff 형식).
- **컴파일 증거** — 컴파일 실행 결과(`error CS=0` 확인 등). 로그 경로 또는 원문 발췌.
- **작성 테스트 명세** — 새 테스트가 있다면 테스트 파일 경로 + 테스트 항목 목록 (실행 판정은 QA 서브에이전트 몫).
- **범위 준수 선언** — "범위 외 파일 수정 없음" 또는 "범위 외 수정 있음: 사유 + 파일 목록".

### 5-2. QA 서브에이전트 제출물 (전부 필수)
- **검증 구분 명시** — 아래 3단계를 **반드시 분리 표기**한다. 하나로 뭉뚱그려 "다 됐다"고 쓰면 무효:
  - ① 컴파일(Compile): `error CS=0` 여부 + 로그 경로
  - ② EditMode 테스트: 실행한 테스트 수/통과 수 + 로그 경로
  - ③ Play 검증: Play 모드에서 확인한 항목 + 스크린샷/로그 경로 (실행했다면)
- **증거물 경로** — 로그 파일, 테스트 리포트, 스크린샷 등 실제 경로. 증거물 없는 판정은 무효.
- **미검증 항목 명시** — 못 돌린 검증이 있으면 "미실행 + 사유"를 숨기지 않는다.

> 감독자는 위 제출물을 **실제로 읽고** (파일 존재, diff 내용, 로그 대조) 수용/반려를 결정한다. 읽지 않고 "제출됐으니 통과" 처리하는 것도 위반이다.

## 6. 프로젝트 규칙 보존 (감독자·서브에이전트 공통 — 기존 관행 그대로 유지)

1. **한국어:** 작업 계획, 보고서, 스펙 문서는 기존 프로젝트 관행대로 한국어로 작성 (코드/식별자는 영어 유지).
2. **범위 파일(scope files) 준수:** 위임 시 지정한 파일 화이트리스트만 수정. 범위 밖 수정이 필요해지면 **즉시 보고하고 승인을 받은 뒤** 진행 — 먼저 고치고 사후 보고 금지.
3. **`git add -A` 금지:** 스테이징은 파일 단위로 명시 지정. `git add .` / `git add -A` / `git commit -a` 모두 금지.
4. **무관한 더티 워크 보호:** 작업 전 `git status`로 기존 변경분을 파악하고, **이번 작업과 무관한 더티 파일은 절대 손대지 않는다** (revert/stash/체크아웃으로 덮어쓰기 포함). 사용자가 미커밋 작업 중인 파일이 범위에 걸리면 감독자가 사용자에게 확인 후 진행.
5. **검증 3단계 구분:** 컴파일 / EditMode / Play는 서로 다른 단계로 취급하며, 낮은 단계 통과가 높은 단계 보증이 아님 (컴파일 OK ≠ Play OK). 보고서에서 반드시 구분 표기.
6. **승인 게이트(Approval Gates):**
   - **Play 모드 검증 실행** 전 — 사용자 승인 필요 (위임 계획에 "Play 검증 예정" 명시 후 승인 받아 진행).
   - **커밋(commit)** 전 — 사용자 승인 필요. 승인 없이 서브에이전트가 커밋 금지.
   - 승인은 감독자가 사용자에게 요청하고, 결과를 서브에이전트에 전달한다. 서브에이전트가 임의로 게이트를 통과 판정하지 않는다.

## 7. 위임 실패 시 복구 절차 (Recovery — 침묵 인계 금지)

서브에이전트가 실패/부재/무응답이거나 증거물이 불충분할 때:

1. **대행 금지:** 위임 실패를 이유로 감독자가 직접 코딩·QA를 대신 실행하는 것은 **금지** (§3-1~5, §3-6).
2. **실패 기록:** 무엇을 위임했고, 어떻게 실패했는지 (에러 메시지, 시점, 재시도 횟수)를 보고서에 기록.
3. **재위임 시도:** 동일 태스크를 1회 재위임 가능 (지시를 더 구체화해서). 재시도도 실패하면 재시도 중단.
4. **사용자 지시 요청:** 실패 상황과 선택지(예: "구현 서브에이전트 재생성", "범위 축소", "이번만 감독자 직접 실행 특별 승인")를 보고하고 **사용자의 지시를 기다린다**.
5. **특별 승인 예외:** 사용자가 명시적으로 "이번 작업은 감독자가 직접 실행하라"고 승인한 경우에만 예외 허용 — 보고서에 `직접 실행 예외: 사용자 승인 문구/시각`을 기록하고, 이때도 QA는 가능한 한 별도 서브에이전트에게 위임한다.
6. **부분 결과 보존:** 실패한 서브에이전트가 남긴 부분 산출물(diff 조각, 로그)은 삭제하지 말고 그대로 두어 사용자 판단 재료로 제공.

> **"조용히 해결했다"는 이 정책 하에서 가장 심각한 위반이다.** 실패는 보고할 가치가 있는 정보다.

## 8. 위반 판정 (Enforcement)

다음 중 하나라도 해당되면 그 작업은 **정책 위반**으로 판정하고, 산출물을 재검증 대상으로 돌린다.

- [ ] 감독자가 수정한 `Assets/` 또는 `Tests/` 코드 파일이 존재 (diff 작성자 확인)
- [ ] 감독자가 직접 실행한 컴파일/테스트 로그를 근거로 QA 판정을 보고
- [ ] 구현과 QA가 같은 서브에이전트에서 겸직됐는데 겸직 선언·사용자 승인 없음
- [ ] diff/증거물 경로 없이 "완료/통과" 보고
- [ ] 컴파일/EditMode/Play가 구분되지 않은 QA 보고
- [ ] `git add -A` 사용, 범위 외 파일 수정, 무관 더티 파일 변경
- [ ] 위임 실패를 보고 없이 감독자가 침묵 대행

**자기 점검 체크리스트 (최종 보고 전 감독자 필수 확인):**

1. 이번 작업에서 코드 파일을 **직접** 수정한 적이 없는가? (스펙/정책 문서만 수정했는가?)
2. 모든 코드 변경이 구현 서브에이전트 diff로 제출됐는가?
3. QA 판정이 전부 QA 서브에이전트 증거물에 근거하는가?
4. 컴파일/EditMode/Play가 각각 구분 표기됐는가?
5. 미검증 항목을 숨기지 않았는가?
6. Play/커밋 승인 게이트를 지켰는가?
7. 위임 실패가 있었다면 보고하고 사용자 지시를 받았는가?

### 최종 보고서 필수 선언란 (템플릿)

```
- 위임 준수: ✅ (구현: <서브에이전트> / QA: <서브에이전트>) 또는 ⚠️ 예외 사유 기록
- 감독자 직접 코드 편집: 없음 (문서만) / 있음 → 사용자 승인 문구 기록
- 수정 파일: <경로 목록>
- diff 근거: <diff/커밋 해시>
- 컴파일: <증거 경로> | EditMode: <증거 경로> | Play: <증거 경로 또는 미실행 사유>
- 승인 게이트: 커밋 승인 <여부>, Play 승인 <여부>
- 범위 외 수정/무관 더티 변경: 없음 / 있음 → 상세 기록
```
